# 현재 위치 수집·표시 복구

2026-11-06. API 계약·백엔드·방문 인증 조건은 변경하지 않았다.

원인: 위치 수집 함수가 accuracy>20m인 유효 좌표까지 거부했고 첫 요청 실패 시 watch를 시작하지 않았다. 오류는 시각적으로 숨겨졌으며 개발 기본 진입은 고정 가상 좌표를 사용했다. 지도 중심은 서비스 범위로 제한되므로 좌표가 없거나 지역 밖일 때 지도 중심을 현재 위치로 해석하면 안 된다.

변경:
- 기본 진입은 개발/배포 모두 브라우저의 실제 위치를 요청한다. 개발의 명시적 시연 도구는 유지한다.
- 유효한 저정확도 좌표도 수신하고 관측 시각·오차를 보존해 이후 갱신한다. 신문 방문 판정은 기존 accuracy<=20m, distance<=20m, freshness 조건을 유지한다.
- 초기 timeout/일시적 실패 후 착지 상태에서 watchPosition으로 복구한다. 권한 거부·비보안환경·미지원은 자동 추적하지 않고 사용자 안내를 표시한다.
- 오류/대략 위치/지역 밖/첫 위치 대기 안내와 재시도 버튼을 기본 화면에 표시한다. 부정확하거나 범위 밖 좌표에서는 홍길동을 확정 현재 위치처럼 표시하지 않는다. 지도 카메라 범위 제한은 유지하며 원 좌표를 서울 좌표로 바꾸지 않는다.
- 새 실제 watch 결과는 demo 출처 상태를 해제한다. 위치 데이터·권한·좌표를 로그/영속 저장하지 않는다.

검증: 수정 전 실패한 위치 수신·초기 timeout 복구 회귀를 확인하고 구현했다. 25 suites/85 tests 및 production build 통과. 유효 저정확도수집, 정확도개선, 20m신문잠금, 권한거부추적안함, HTTPS안내, 지역밖홍길동숨김을 확인했다. 실제 배포URL/물리기기/현장GPS는 검증하지 않았다. 브라우저·운영체제가 잘못 보고하는 좌표의 절대정확도를 코드로 보장할 수 없다. HTTPS·기기/사이트 권한·iframe Permissions-Policy 허용은 운영환경의 전제다.

Plan/Design: 위치수신과방문인증 분리,원좌표와지도카메라 구분. Build: 기존 React/CSS 함수수정. Test: 실패회귀→수정→전체테스트/빌드/독립리뷰. 명명 전용 스킬 미설치로 동등 직접절차. Deploy: 코드PR, 실제 운영배포는별도.
